    piiguard

    A PII leak guard for sandboxed AI agents that hardens itself. Sandboxes decide where an agent may send data; piiguard checks what is inside it.

    Picked from 109 projects at the Recursive Agents Hackathon, San Francisco, October 2026. Built solo in one day, 65 commits.

    agent in OpenShell→guard proxy→allowed API→restore tokens
    red team attacks→coach rewrites rules→gate→git tag gen-N↺
    • The gap: an agent allowed to call a search API can paste a customer's SSN into the query, and the sandbox lets it through because the host is on the allow-list.
    • Guard proxy: swaps PII for reversible tokens before anything leaves the sandbox, then restores the real values on the way back so the agent still finishes its job.
    • Red team: Nemotron 3 Super on Crusoe tries to sneak PII past the guard with base64, hex, reversed strings, spelled-out digits, and unicode tricks.
    • Coach and gate: a coach rewrites the rules from what leaked. A change is kept only if leaks drop and false positives don't rise, and every accepted generation is a git tag, so reviewers read a regex diff, not a black box.
    • Results on held-out attacks: leak rate 76.7% to 16.7% with rules alone and zero false positives; 0 of 30 with the Nemotron 3.5 Lightning classifier; insurance pack 90% to 20%; 92.8% recall on structured identifiers in NVIDIA's Nemotron-PII set vs 68.5% for Presidio.

    Presidio still leads on semantic PII like names and places. The repo publishes that too.

    Read the case study → Repository ↗ Demo video ↗ Award post ↗
  • Open sourceSelf-improvingAgent security

    AgentShield

    A guardrail proxy for agent-to-agent traffic that learns new PII rules from its own misses and unlearns the ones that misfire.

    agent A→regex + Presidio→agent B
    auditor finds miss→synthesize rule→validator gate→human approves→hot-load↺
    • Fast path: compiled regex and Presidio, no LLM inline, so latency stays predictable.
    • Learns: an async LLM auditor reviews traffic for leaks the rules missed. A synthesizer turns each miss into a candidate regex rule and retries on validator feedback.
    • Gated: a candidate must pass false-positive checks on 500 clean messages and precision/recall on a labeled eval set, then get human approval. It hot-loads through a MongoDB change stream with no restart.
    • Unlearns: the gateway tracks live hits per rule. A rule with over 20% false positives across 5+ hits from 2+ sessions is proposed for retirement, demoted to shadow, and pulled from the live gateway.
    • Every change writes a new eval generation, so improvement is measured over time. The auditor never sees raw values, only their shape.

    Conduit

    A proxy-first AI gateway. Every model call goes through one OpenAI-compatible API.

    auth→ingress guard→router→provider adapter→egress guard→telemetry
    • Six-stage pipeline every call must pass through. Vendor SDKs are isolated and enforced in CI, so swapping providers is a config change.
    • Two-stage router: a zero-cost heuristic resolves 80%+ of traffic, and a cached LLM tie-break handles the rest. 50.8% cheaper than all-frontier routing.
    • Guards: DLP and Presidio redaction with lossless entity rehydration, and prompt-injection detection at 100% on a held-out probe.
    • An LLM-as-judge suite blocks CI on any quality regression. Built with FastAPI, LangGraph, and pytest; routes across Claude, GPT, and Ollama.

Watch AgentShield learn and unlearn

A replay of a real run. Every message, finding, regex, and verdict below is from the run's recorded outputs, on synthetic data.

Recorded replay
Step 1 of 7

A message slips through

Generation 0 runs Presidio only. It catches the name and phone, wrongly tags part of the claim ID as a phone number, and lets the policy number and adjuster badge through. The Claims agent repeats them back.

Intake agent sends (synthetic)
Hi, this is Maria Gonzalez. My car was hit in a parking lot. Policy INS-AZ-4471-K. Adjuster ADJ#77-1043 came by and said claim CLM-2026-000913 is pending. You can call me at (415) 555-0134.
Claims agent replies (recorded)
Claim CLM-[PHONE #e861] is currently pending under policy INS-AZ-4471-K. Adjuster ADJ#77-1043 has been assigned and is handling the review.
Step 2 of 7

The auditor catches it, off the hot path

An LLM auditor reviews forwarded traffic after delivery, so it adds no latency. It sees only the shape of each value, never the raw value.

Auditor findings (recorded)
INS-AZ-4471-KINSURANCE_POLICY_NUMBERconfidence 0.99
ADJ#77-1043ADJUSTER_BADGEconfidence 0.99
Step 3 of 7

Each miss becomes a candidate rule

A synthesizer turns every finding into a compiled regex with its own positive and negative test cases, and retries on validator feedback.

Synthesizer drafts (recorded)
\bINS-[A-Z]{2}-\d{4}-[A-Z]\b(?<![A-Z0-9-])\bINS-[A-Z]{2}-\d{4}-[A-Z]\b(?![A-Z0-9-])(?<![A-Za-z0-9-])\bADJ#\d{2}-\d{4}\b(?![A-Za-z0-9-])

Each draft ships with 8 should-match and 8 to 12 should-not-match examples, such as SKU-INS-AB-1234-C and ADJ#12-3456A.

Step 4 of 7

Validated, approved, hot-loaded

A rule only goes live after it passes false-positive checks on 500 clean messages and precision/recall on a labeled eval set, and a human approves it. A MongoDB change stream pushes it into the running gateway with no restart.

Gateway log
rule … ACTIVE (INSURANCE_POLICY_NUMBER) -> liverule … ACTIVE (ADJUSTER_BADGE) -> live

Every approval also writes a new eval generation, so the improvement is measured, not assumed.

Step 5 of 7

Next time, it holds

The same kind of message now goes through the compiled rule in microseconds. No LLM call on the request path.

Claims agent replies (recorded)
Claim CLM-[PHONE #e861] is received and currently pending review. Adjuster [ADJUSTER_BADGE #2c5d] has been assigned to the claim.
Step 6 of 7

Then the rule starts misfiring

Marketing launches products whose codes look exactly like policy numbers. The live rule tokenizes them, and a hit review judges each match in context.

Message from a separate session
New brochure for product INS-TX-0042-A ships Monday to all branches.

not personal The matched value is identified as a product reference in a brochure distribution message, not an identifier tied to a person, account, policy, or claim.

Message from a separate session
Please add product code INS-FL-0777-D to the spring catalog price list.

not personal The value is explicitly described as a product code for a catalog, so it is not tied to a specific person, account, policy, or claim.

Message from a separate session
Pricing team approved a 5% discount on the INS-OR-0220-F starter package.

not personal The value is described in connection with a starter package discount, indicating a product or package reference rather than a person-, account-, policy-, or claim-specific identifier.

Plus three more like these, six sessions in all.

Step 7 of 7

And it unlearns

6 of the policy rule's 7 live hits were judged not personal. That's an 86% false-positive rate, far past the 20% limit, across 5+ hits from 2+ sessions. Retirement is proposed, a human approves, and the rule is demoted to shadow and pulled from the live gateway.

Gateway log
rule … now shadow -> removed from live set

This is why the real engine in the console above ships with the badge rule but not the policy rule.
